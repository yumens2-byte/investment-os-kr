# X Reply Engine 품질 강화 상세설계 및 반영 전 검증

작성일: 2026-10-29 KST
대상: yumens2-byte/investment-os-kr
기준: 운영 감사 보고서 X_Reply_Engine_Beta_Audit_20261029.md 및 runtime bbf9aecd9d482109c96372e9b95a260b30e03f75.
작업 브랜치: codex/reply-quality-predeploy-20261029.

## 1. 문제와 범위

Actions 성공 여부는 답글의 의미 정확성이나 실제 게시 확인을 보장하지 않는다.
감사 보고서는 최근 22회에서 실제 발행의 덕담 오독 1건, 발행 결과 불명 2건,
범용 대체문구에 따른 맥락 손실을 확인했다. 실제 발행 전체의 오답률은 측정하지 않았다.

이번 작업은 의미·맥락 게이트, 안전 대체문구, 품질 관측 및 오프라인 회귀 검증을 강화한다.
기존 bbf9aec의 후보 3개 생성, 역할 역전 방어, 세션 초기화, timeout, 404 조합 생략을 재사용한다.
예약·상한·질문/부정댓글 무응답·타인 스레드/자기댓글 제외 정책은 변경하지 않는다.
운영 DB 접속·수정, 외부 댓글 발행, workflow dispatch, main 병합, 승인 런타임 SHA 변경은 수행하지 않는다.

## 2. 책임과 처리 흐름

| 단계 | 책임 | 변경 |
|---|---|---|
| policy.intent_for | 댓글 의도 분류 | 기존 의미 우선순위 유지 |
| generator | AI 후보와 의도별 대체문구 제공 | 생성 프롬프트·모델 호출 규약 유지 |
| gate.check_reply | 후보 단건 검증 | 덕담 시제·행위 역전 어미 확장, 명시적 의도의 범용문구 차단 |
| gate.choose_reply | AI → AI_ALT → TEMPLATE_FALLBACK → 무응답 | 순서·상한·유사도 방어 유지 |
| run_reply | 저장·발행·결과 기록 | 실제 게이트 수행 여부·의도 기록 |
| telemetry | 검증 분모와 결과 분리 | 고유 평가 댓글 기반 품질 지표 추가 |

모든 후보에 동일 게이트를 적용한다. 안전 풀도 예외 처리하지 않으며,
유사도 등으로 풀이 소진되면 무응답한다. API 재생성·추가 호출은 없다.
품질 게이트는 외부 발행과 기존 이력 저장 전에 실행된다.

## 3. 의미 역전 방어

기존 GREETING 규칙은 `~되셨다니` 등 일부 어미만 검출한다.
`~먹었다니`, `~쉬셨다니`, `~보내셨네요`, `~드셨군요` 등 과거 경험 단정형을 추가 차단한다.
반환 코드는 기존 GATE_ROLE_REVERSAL을 사용한다.

GREETING 판정 때만 적용하므로 “저녁 맛있게 먹었어요” 같은 실제 경험 진술에는
“맛있게 드셨군요”가 허용된다. 기원과 경험의 대조 테스트로 과차단을 검증한다.
문자열 규칙이 모든 의미 오류를 검출한다는 보장은 없다. 인사와 경험이 섞인 댓글은
보수적으로 차단될 수 있으며 실제 모델 shadow 검수가 필요하다.

## 4. 범용 대체문구와 근거 없는 사실 방어

GREETING/WORRY/OPINION/CHOICE에 한해, 구두점·이모지·공백을 제거한
정확 일치 문구(“댓글 잘 봤어요”, “반응 남겨주셔서 고맙습니다” 등)를 GATE_INTENT로 차단한다.
단어 겹침으로 의미 일치를 추정하지 않는다. ACK·순수 감사 등 일반 호응은 유지한다.
이는 제한된 관측 문구 방어이며 모든 범용 답글 검출기가 아니다.

WORRY 안전 풀의 “변동이 커서”, “흔들리는 장”, “숫자가 크게 움직여서”는 댓글에 없는
시장 상태를 단정할 수 있어 제거한다. 대신 마음·걱정 표현을 받아주는 중립 문구를 사용한다.
투자 방향·수익 전망·조언은 추가하지 않는다.

## 5. 관측 명세

X review 항목에 quality_evaluated(boolean), intent(string)를 추가한다.
quality_evaluated는 실제 후보 게이트를 수행한 행에만 true다. cap 등으로 생성 이전에
탈락한 행은 분모에서 제외한다. DB 스키마 변경은 없고 기존 메타데이터 형식도 보존한다.

공통 report에 quality_metrics를 추가한다. 기존 source_counts는 하위호환을 위해 유지한다.

| 필드 | 정의 |
|---|---|
| coverage | unique_evaluated_observations_only |
| evaluated | 댓글 ID별 마지막 평가 행 수 |
| selected | 평가 행 중 PUBLISHED/PUBLISHED_DB_UNCONFIRMED/SIMULATED 수 |
| rejected_first_drafts | 첫 후보 탈락 사유가 기록된 고유 평가 댓글 수, 대체 성공 수와 다름 |
| draft_gate_reasons | 첫 후보 탈락 사유 집계, 모든 후보의 사유 집계가 아님 |
| actual_sources | live에서 게시 확인된 선택 행의 생성 경로별 수 |
| simulated_sources | SIMULATED 행의 생성 경로별 수 |
| template_selection_rate | 선택된 결과 중 TEMPLATE_FALLBACK 비율; 선택 0건이면 null |
| human_review_required | true |
| semantic_quality_verified | false; 게이트 통과로 의미 품질을 입증하지 않음 |

PUBLISH_UNKNOWN은 선택 결과와 발행 성공 분자에서 제외한다. 기존 transport_metrics로
발행 불확실성을 별도 관찰한다. 보고서 지표는 제공된 실행 관측 범위이며 전체 DB 코호트나
고유 신규수집 전환율을 의미하지 않는다. 평가 표식이 없는 과거/FB 행은 이번 지표에서 제외되므로
0은 “완전한 평가 없음”일 수 있다. FB 게이트·안전 풀은 공유되지만 X 신규 평가 표식은 FB에 추가하지 않는다.

## 6. 장애·정합성·보안

- 기존 이력 저장 실패 시 발행 금지, cap 예약/해제, timeout, 결과 불명 재발행 금지를 유지한다.
- PUBLISH_UNKNOWN 6건의 실제 게시 여부는 이번 작업에서 확인하지 않는다. 자동 재시도/DB 상태 변경 금지.
- 신규 관측은 기존 artifact 구조에 상태·의도만 추가하며 비밀값은 기록하지 않는다.
- 공유 gate/policy/telemetry는 Facebook에도 영향을 줄 수 있어 전체 FB 회귀 테스트를 포함한다.
- 추가 네트워크·모델 호출, 추가 DB 트랜잭션·테이블·인덱스는 없다.

## 7. 검증과 반영 조건

신규 테스트는 사고 재현, 존댓말/비존댓말 시제 변형, 경험 진술 허용,
의도별 범용문구 차단·대체, 풀이 소진된 무응답, 비시장 걱정,
평가 분모·중복제거·UNKNOWN 제외, shadow/live mock 통합을 포함한다.
전체 tests/와 CI 정적검사를 실행한다. 외부 호출은 테스트 대역으로 차단한다.

운영 반영 이후 별도 승인으로 진행할 검증:
1. 인사·식사/휴식·축하·불안·선택·긴 의견 등 유형별 실제 AI shadow 원문/최종문구 검수.
2. 의미 역전·근거 없는 사실·투자 지지·톤 불일치가 발견되면 보완 후 재검수.
3. 기존 상한 이내 제한 live로 발행 결과 및 저장 정합성 확인. 결과 불명은 실제 게시 대조 전 재발행 금지.
4. 변경 전후 고정문구 비율·첫 후보 탈락·적격 전환율은 동일 분모/버전/모드로 비교.

main Gemini 키 404 원인, shadow history 저장 충돌, 실제 스케줄 횟수, 장시간 유휴 연결 문제는
별도 미해결 운영 과제다. 오프라인 테스트로 해결 또는 운영 안정화를 선언하지 않는다.

## 8. 검증 결과 및 변경 관리

- Python 3.11.17, requirements-reply.lock, pytest 9.1.1: 전체 **976 passed** (6.79초).
- 이번 신규 회귀: **22건**. 기준 runtime의 기존 전체 954건 대비 증가분.
- Python 3.12.14에서도 동일 976건 통과 (3.30초).
- CI 정적검사 대상 + scripts/ 전체 + 신규 테스트 ruff 0.16.10 통과; git diff --check 통과.
- JUnit: evidence/tests/reply_quality_predeploy_20261029.xml.
- 초기 검증은 의존성 설치 완료 전 수집 오류, 이후 신규 통합 테스트의 분류기 대역 누락 2건을 수정했다.
  최종 검증에는 이 오류가 없다. 전체 scripts/ 검사에서 발견된 기존 요약 스크립트 행 길이도 함께 정리했다.

영속 요약 scripts/publish_summary.py도 실제 발행·모의·결과 불명을 구분한다.
모드나 artifact가 없으면 발행을 0으로 단정하지 않고 미확인으로 표시한다.
기존 reply_summary.yml의 workflow_run 이름 `reply-engine`과 현재 엔진 이름 `X Reply Engine`은
일치하지 않는다. 이번에 YAML은 수정하지 않았으며 영속 요약 자동 실행 자체는 미검증·별도 조치 대상이다.

브랜치 기준 주의: main은 f4f1331이고 승인 runtime은 bbf9aec다. 따라서 main 대상 PR은
이미 runtime에 포함된 30da9b0, bbf9aec 선행 2커밋을 함께 포함한다.
이번 신규 커밋의 차분과 선행 변경을 구분해 검토해야 한다.
main 병합·REPLY_RELEASE_SHA 변경·운영 모드/예약 변경·수동 외부 발행은 하지 않았다.

판정: **오프라인 구현·회귀 검증 완료, 운영 전 실제 AI shadow 검수 미완료.**
정규식 기반 방어와 제한된 표본이므로 전체 의미 정확도나 향상률을 산출하지 않는다.

## 9. 3인 독립 코드리뷰 및 최종 전수검증 (2026-10-29)

사용자 운영 반영 승인에 따라 의미/품질, 관측/집계, 배포/통합의 독립 리뷰 3건을 수행했다.

| 리뷰 | 지적 | 보완·재검토 |
|---|---|---|
| 의미/품질 P2 | 정규화로 ㅎㅎ가 제거되어 범용 인사 차단 누락 | 차단 집합을 정규화 결과와 일치시킴. 유형별 회귀 통과 |
| 의미/품질 P3 | 좋았/행복했이 운영자 자신의 감정도 과차단 | 광범위 감정 어간 제거. 정상 감정 허용과 경험 역전 차단 대조 통과 |
| 관측/집계 P2 | skip_reasons 누락/null을 UNKNOWN 0으로 표시; 잘못된 숫자 표시 | 유효 dict/비음수 int만 집계, 나머지 미확인. bool·문자열·음수·null 회귀 통과 |
| 배포/통합 P1 | workflow_run 구독 이름 불일치로 요약 자동 실행 안 됨 | reply_summary.yml의 구독을 X Reply Engine으로 수정, 연결 이름 회귀 추가 |

3명 모두 수정 후 재검토에서 해당 결함 해소 및 추가 차단 결함 없음으로 보고했다.
이는 독립 에이전트 코드리뷰이며 실제 운영자 3명의 승인으로 간주하지 않는다.

최종 동일 코드, Python 3.11.17, lock 의존성, pytest 9.1.1:
- 전체 전수 1회: **991 passed**, 3.34초, 실패/오류/스킵 0.
- 전체 전수 2회: **991 passed**, 3.40초, 실패/오류/스킵 0.
- 이번 품질 회귀 파일: 37건. 기존 runtime 대비 전체 37건 증가.
- CI 범위 정적검사와 scripts/ 전체 및 신규 테스트 ruff 통과; git diff --check 통과.
- JUnit 증거: evidence/tests/reply_quality_review_round1_20261029.xml, reply_quality_review_round2_20261029.xml.

8절의 “요약 트리거 미수정”은 당시 상태이며 이번 보완으로 해소했다.
실제 AI 의미 검수·실게시·미해결 UNKNOWN 실제 대조는 위 모의 회귀검증과 구분한다.
운영 반영은 main 병합과 승인 runtime SHA 설정을 각각 확인해야 완료된다.
