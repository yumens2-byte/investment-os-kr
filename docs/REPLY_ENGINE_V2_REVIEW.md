## 독립 검수와 통합테스트

3개 독립 AI 리뷰 에이전트가 발행 안전성, 답글 품질, SDK·운영 통합을 각각 검토했다. 사람 3명의 GitHub 승인 리뷰를 받은 것은 아니다.

- 리뷰 1: 안전성 회귀 11건 통과. 처음 재현한 일일·타인 스레드 상한, claim 날짜 문제 해결 확인.
- 리뷰 2: 품질 회귀 43건 통과. 비판을 긍정으로 분류하는 문제와 부적절한 fallback 해결 확인.
- 리뷰 3: 실제 SDK 오프라인 통합 6건 통과. 운영 베타 실행기 검토에서 차단 문제 없음.
- 전체 테스트: **640 passed, 13.64초**. 기존 PR 569건에 리뷰·통합·베타 회귀 71건 추가.
- Ruff 및 git diff --check 통과.

통합테스트는 실제 파이프라인 모듈을 실행한다. Tweepy의 JSON 요청·응답 처리, PostgREST SDK의 조건부 claim/조회/쓰기, Gemini gateway를 사용하고 외부 HTTP 및 Gemini SDK 호출 경계만 대체한다. 성공 발행 저장·커서·예산, timeout 후 재발행 차단, 보류 다음 실행 복구, dry-run 무변경, 이전 날짜 당일 상한, 재수집 분류 장애 3회 제한을 검증했다.

모의 HTTP는 실제 운영 Supabase/X/Gemini의 권한·모델 출력·네트워크 상태를 입증하지 않는다. 이 구간은 운영 베타에서 확인한다.

## 승인된 운영 반영과 1회 베타

GitHub 연결 도구에 workflow_dispatch 기능이 없어, main 병합에서 지정 문구와 문서 경로가 함께 변경될 때 실행하는 별도 workflow를 추가했다.

- workflow: .github/workflows/reply_engine_beta.yml
- 조건: main push + 이 문서 변경 + commit message에 reply-engine-v2-approved-beta 포함.
- 정기 스케줄 없음. 반복하려면 같은 조건을 의도적으로 충족하는 새 commit이 필요하다.
- 기존 reply-engine concurrency를 공유하고 전체 테스트를 선행한다.
- 운영 DB 스키마·정합성 읽기 검사 → dry_run → 실제 dry_run API 읽기 사용량 예산 저장 → live → 사후 DB 검사.
- 베타 live는 최대 1회 발행 시도, 좋아요 비활성. 기존 운영 Variables와 스케줄은 변경하지 않는다.
- dry_run 사용량 저장 실패나 사전 검사 실패 시 live를 수행하지 않는다.
- 처리할 적격 댓글이 없으면 실행은 성공할 수 있으나 publication_verified=false이므로 실제 발행 검증 완료라고 보고하지 않는다.
- 결과 artifact: reply-beta-<run_id>, logs/reply_beta_report.json 및 건별 리포트.

운영 반영/베타 완료 여부는 GitHub의 실제 merge SHA 및 Actions 결과로 확인한다. 이 문서 작성 시점에는 아직 반영 전이며, 결과를 추정해서 기입하지 않았다.

## 남은 범위와 한계

- 실제 댓글 자연스러움·오분류율·스킵 감소율은 운영 원문 표본으로 평가해야 한다. 단위/통합 테스트 통과가 그 수치를 입증하지 않는다.
- 질문 자동 답변·타인 스레드/링크 opt-in 기본 비활성·신생 계정 휴리스틱은 이전 정책을 유지한다.
- emoji 패턴은 Unicode 전체 grapheme를 보장하지 않는다.
- 복구 500행 검사 상한을 넘는 backlog와 최초 수집 불완료는 리포트로 감시한다.
- reply/following의 공용 예산은 기존 read-modify-write 방식이다. 서로 다른 workflow의 동시 갱신은 별도 원자적 예산 설계 대상이며 following은 현재 비활성 상태다.
- 결과 불명 및 과거 PUBLISH_FAIL은 실제 발행 여부를 확인하여 수동 정리한다. 자동 재발행을 켜는 운영 조치는 하지 않는다.
