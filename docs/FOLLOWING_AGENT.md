# Following Agent 24시간 보수 운영 설계

마지막 검토: **2026-09-17**

## 1. 목표와 비목표

Following Agent는 팔로잉 홈 타임라인에서 투자 도메인과 직접 관련된 글만 골라 자연스러운
한국어 코멘트 후보를 만든다. 코멘트는 60자 이하의 한국어 한 문장으로 제한한다.
워크플로우는 매시 23분에 하루 24회 실행하고, 실행마다
`1~5` 사이의 **후보 상한**을 무작위로 선택한다. 이 숫자는 발행 목표나 하한이 아니다.
확실한 후보가 없다면 0건으로 끝나는 것이 정상이며, 수량을 채우기 위해 점수나 안전
게이트를 완화하지 않는다.

타인 글에 직접 다는 자동 답글은 활성화하지 않는다. `PERMITTED_REPLY`는 문안을 만들고
`REVIEW_ONLY/READY`로 저장할 뿐 X Write를 호출하지 않는다. 실발행 가능한 자동 액션은
기존과 같이 신뢰 작성자 allowlist의 `QUOTE`뿐이며, 저장소 스위치와 수동 dispatch의
`confirm_live`가 동시에 참이어야 한다. 따라서 정기 schedule은 `live` 변수가 잘못
설정되어도 승인값이 없어 발행하지 못한다.

## 2. 실행 흐름

1. `FOLLOWING_ENABLED` kill switch와 `dry_run/shadow/live` 모드를 확인한다.
2. `FOLLOWING_RUN_TARGET_MIN/MAX`를 각각 1~5로 보정한 뒤 실행 상한을 무작위 선택한다.
3. 공유 API 예산, X 자격 증명, 홈 타임라인 읽기를 fail-closed로 검사한다.
4. 자기 글, 차단 작성자, 짧은 글, 광고·프로모션, 비관심 주제를 정적 필터링한다.
5. Gemini가 관련성·내용 가치·참여 가치와 문안을 구조화 JSON으로 평가한다.
6. 세 핵심 점수의 최솟값이 높은 순으로 정렬한다. 하나의 약한 점수를 높은 평균으로
   숨길 수 없으며 중요도는 동점 해소에만 쓴다.
7. 원문에 없는 수치, 멘션·링크·해시태그, 질문, 지시·권유, 확정적 인과·전망,
   원문 복사, 분석형 상투어, 줄바꿈·비정규 Unicode, 최근 문안과의 유사성을 차단한다.
   같은 배치에서 먼저 선택된 검수 후보도 즉시 유사도 비교 목록에 넣는다.
8. 실행 무작위 상한, 일일 절대 상한, 작성자 24시간 cooldown, 중복 이력, 비용 예산을
   통과한 액션만 모드별로 처리한다.
9. JSON 리포트에 선택된 `run_target`, 퍼널, 스킵 사유, 검수 문안을 남긴다.

## 3. 자연스러운 문안 기준

- 글쓴이에게 직접 말하는 12~45자 한 문장을 목표로 하며, 60자를 절대 넘지 않는다.
- 뉴스 전체를 다시 요약하지 않고 원문에서 확인되는 한 지점만 언급한다.
- 과장된 칭찬, 상투적 인사, 글쓴이 말투 모방, 실제로 없는 친분 암시를 사용하지 않는다.
- 새로운 사실이나 숫자, 투자 판단, 매수·매도 권유, 전망, 외부 링크를 만들지 않는다.
- 질문으로 대화를 유도하거나 수량을 채우기 위한 범용 문구를 만들지 않는다.
- `중요한 신호`, `가능성을 보여줍니다`, `시사합니다`, `도움이 됩니다`처럼 어느 글에도
  붙일 수 있는 분석형 상투어는 결정 게이트에서 차단한다.
- `PERMITTED_REPLY`는 같은 텍스트 검증을 통과해도 사람이 원문 맥락을 확인하기 전에는
  발행하지 않는다.
- 점수 미달 `NEAR_MISS_SCORE`와 모든 `SKIP`의 미검증 LLM 문안은 리포트와 DB에서 비운다.

## 4. 빈도와 안전 상한

| 설정 | 기본값 | 의미 |
|---|---:|---|
| cron | `23 * * * *` | UTC 기준 매시 23분, 24시간 |
| `FOLLOWING_RUN_TARGET_MIN` | `1` | 실행별 무작위 후보 상한의 하한(1~5 보정) |
| `FOLLOWING_RUN_TARGET_MAX` | `5` | 실행별 무작위 후보 상한의 상한(1~5 보정) |
| `FOLLOWING_MAX_ACTIONS_PER_RUN` | `5` | 코드의 실행당 절대 상한 |
| `FOLLOWING_MAX_ACTIONS_PER_DAY` | `24` | 하루 실제 액션 절대 상한; 시간당 최대치의 합보다 보수적 |
| `FOLLOWING_AUTHOR_COOLDOWN_HOURS` | `24` | 동일 작성자 반복 관여 방지 |
| 코멘트 절대 상한 | `60자` | 한국어 한 문장, 줄바꿈·질문·느낌표 금지 |

GitHub Actions schedule은 정확한 시각 실행을 보장하지 않는다. `concurrency`는 지연된 실행과
다음 실행이 겹칠 때 둘을 직렬화하며, 수량을 보충하는 catch-up 실행은 하지 않는다.

## 5. 배포 절차

1. `FOLLOWING_ENABLED=false`, `dry_run`에서 리포트 구조와 0건 정상 종료를 확인한다.
2. 기능 스위치만 켠 `dry_run`으로 실제 수집·분류 범위를 확인한다.
3. 최소 72시간 `shadow`로 운영하며 모든 `review` 문안을 사람이 전수 검수한다.
4. 오분류, 사실 추가, 반복 문구가 하나라도 있으면 임계값을 낮추지 말고 원인을 수정한다.
5. 필요한 경우에만 신뢰 작성자 숫자 ID를 최소한으로 등록한다. 첫 live는 수동 dispatch에서
   `confirm_live=true`로 1회 실행하고 결과를 확인한다.
6. 정기 schedule에는 수동 승인값이 없으므로 자동 답글/인용 발행 용도로 사용하지 않는다.

## 6. 테스트와 롤백

로컬 전수 검증은 아래 명령을 연속 3회 실행한다.

```bash
ruff check following_engine run_following.py tests/test_following*.py tests/test_env_hardening.py
pytest -q tests/
```

운영 중 갑작스러운 후보 증가, 반복 작성자, 사실 추가, 403/429, 예산 경고가 보이면
`FOLLOWING_ENABLED=false`로 즉시 중지한다. 이미 시작한 run도 취소하고 원인 확인 전에는
`dry_run`만 사용한다. 무작위 상한은 정책 준수나 탐지 회피 수단이 아니라 매 실행의 처리량
편중을 줄이기 위한 장치다.
