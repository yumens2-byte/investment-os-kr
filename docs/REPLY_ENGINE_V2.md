# 자동댓글 v2 개발·운영 계약

개발 기준: 2026-10-02, main `d7d91d395304349623446a5a1ca82894a1f9cf7f`.
기존 DB 컬럼 안에서 구현했다. DB 스키마 변경이나 운영 변수 변경은 포함하지 않는다.

## 처리 순서

수집과 보류 복구 → 자기/범위/차단/명백 스팸/만료/중복 확인 → 루트 작성자 확인 → 맥락 분류 → 초안 → 품질 게이트와 안전 후보 → 상한 예약 → 이력 저장 → 원자적 발행 claim → X 발행 → 결과 저장 → 커서 확정.

분류·루트·게이트에서 탈락한 댓글은 발행 슬롯을 선점하지 않는다. 발행 전 이력 저장이나 claim이 실패하면 예약을 반환한다. 발행 결과 불명은 예약을 소비하며, 회당 상한은 성공 발행뿐 아니라 API 발행 시도도 제한한다. 사용자·대화·일일 집계에는 미해결 발행 상태도 포함한다.

## 자연스러운 응답과 분류

- 단일 👍/🙏 등 등록된 반응을 허용한다. 비어 있는 본문이나 의미 없는 단문은 계속 제외한다.
- 광고/홍보/카톡은 단어만으로 스팸을 확정하지 않는다. 명백한 홍보 유도 및 리딩방·수익 보장 등은 차단한다.
- 긍정과 부정이 섞인 문장·부정문·수사적 칭찬은 맥락 분류로 넘긴다. 실제 질문은 계속 무응답 정책이다.
- 부모 본문은 최대 1000자까지 제공한다. 원글과 부모 작성자 역할은 분리하며, 원문은 지시가 아닌 JSON 데이터로 전달한다.
- 감사·칭찬·웃음·짧은 반응별 안전 문구를 사용한다. 근거가 있는 주제어 재사용은 허용하되 역할 반전·원문 복제·지어낸 경험·투자 행동 유도는 금지한다.
- 답글은 40자, 한 문장, 이모지 0~1개다. 초안이 탈락하면 의도/언어별 안전 후보를 유한 순회한다. 추가 LLM 재생성은 없다.
- 외국어는 기존 정책대로 한국어 정형 문구를 사용한다. 비라틴 언어와 비라틴 혼합 문장도 이 경로에 포함한다.
- JSON 요청 ID 밖의 결과, 중복 ID, 잘못된 타입·라벨·누락 결과를 신뢰하지 않는다. 분류 결과 미확정은 제한적으로 보류한다.
- JSON 출력 크기를 제한하기 위해 모델 배치는 최대 20건이다. 호출 횟수·키 과금 여부·반환 토큰 사용량을 기록한다. 댓글 분류/생성은 유료 키 fallback을 사용하지 않는다. 다른 파이프라인의 기본 유료 fallback 정책은 유지한다.

정규식 게이트와 프롬프트만으로 모든 의미 오류가 제거됐다고 보장하지 않는다. 실제 자연스러움·풍자·역할 반전은 원문을 포함한 replay/검수로 평가해야 한다.

## 단계 확대 플래그

| 변수 | 기본값 | 동작 |
|---|---|---|
| `REPLY_FOREIGN_THREAD_ENABLED` | false | 타인 원글에서 내 부모 댓글에 직접 온 답글 허용. 부모 작성자도 내 계정인지 검증해야 한다. |
| `REPLY_FOREIGN_THREAD_RUN_CAP` | 1 | 타인 스레드 응답의 회당 상한, 허용 범위 1~3. 전체 회당 상한도 동시에 적용한다. |
| `REPLY_LINK_REVIEW_ENABLED` | false | URL 포함 댓글을 맥락 분류에 전달. 긍정 키워드가 있어도 룰 확정으로 우회하지 않는다. |

신규 플래그는 코드 전달만 추가했다. 운영 활성화는 하지 않았다. 질문 자동답변·정정 처리·새 계정 휴리스틱 해제는 이번 응답 정책에 포함하지 않는다.

## 이력 기반 보류 큐

새 테이블 대신 `kr_reply_history.skip_reason`과 기존 `error_message` TEXT에 버전 있는 JSON 메타데이터를 저장한다. 원 댓글 시각, 전체 원문, 부모 본문/ID/작성자, 답글 대상 계정, 발행/분류 시도 횟수, 다음 시도 시각을 보존한다.

회당/일일/사용자/대화 상한, 예산 부족, 루트 조회 미확정, 분류 결과 미확정, 확정된 429 거절을 복구 대상으로 삼는다. 생성 초안이 없어도 다음 실행에서 분류·생성할 수 있다. 오래된 순서로 최대 100건을 복구하고 신규 댓글과 중복 ID를 제거한다. 정적 필터·루트·분류·모든 상한을 다시 검사한다.

TTL은 `original_created_at` 기준이며 재수집/upsert/재시도 시각으로 연장하지 않는다. 발행 최대 3회, 분류 장애 최대 3회, 재시도 간격 최소 15분이다. 상한 때문에 보류만 한 건은 발행 시도 횟수를 증가시키지 않는다. 재수집하더라도 DB에 저장된 시도 횟수를 초기화하지 않는다.

기존 `PUBLISH_FAIL` 행은 발행 여부를 입증할 메타데이터가 없어 자동 복구하지 않는다. 완료 발행·결과 불명·재시도 대기 상태는 멘션 재수집으로 다시 발행할 수 없다.

## 발행 상태와 중복 방지

| 상태 | 의미 | 자동 재발행 |
|---|---|---|
| `skip_reason=null` | 검수·상한·이력 저장을 통과한 READY | claim을 확보한 실행만 발행 |
| `PUBLISHING` | 조건부 PATCH로 확보한 발행 상태 | 금지. 중단됐으면 결과 확인 필요 |
| 성공 응답 ID + responded=true | 발행 성공 | 금지 |
| `PUBLISH_UNKNOWN` | timeout/5xx/응답 미확인 등 | 금지 |
| `PUBLISH_RETRYABLE` | 명시적 429 거절 | 원 댓글 TTL·간격·횟수·상한 내 허용 |
| `PUBLISH_REJECTED` | 명시적 400/401/403/404/422 | 자동 복구 대상 제외 |
| `SPEND_CAP` | 플랫폼 비용 상한 | 자동 복구 대상 제외 |

새 이력은 INSERT, 미발행 이력 변경은 기존 상태를 조건으로 한 PATCH를 사용한다. 기존 발행 ID나 PUBLISHING/UNKNOWN 상태를 무조건 upsert로 덮어쓰지 않는다. 발행 claim은 live·미발행·응답 ID 없음·READY일 때만 원자적으로 성공한다.

발행 성공 뒤 DB 저장이 실패하면 PUBLISHING이 차단 상태로 남고 응답 ID를 포함한 관리자 알림을 남긴다. 성공 저장은 생성 시각을 발행 시각으로 갱신하여 당일 실적이 반영되며 원 댓글 시각은 메타데이터에 보존된다.

X와 DB를 하나의 트랜잭션으로 묶지 않는다. 공식 워크플로의 concurrency와 댓글별 원자적 claim을 함께 사용한다. 다른 실행자가 같은 예산 테이블을 동시에 변경하는 경우까지 전역 예산 원자성을 보장하는 구조는 아니다.

## 모드와 리포트

dry_run은 DB 쓰기와 X 발행을 하지 않는다. shadow는 `kr_main:shadow` 커서를 사용하며 `kr_main` live 커서를 전진시키지 않는다. shadow가 기존 live 이력을 덮어쓰지 못하도록 저장 가드를 둔다.

모든 단계의 제외 사유와 부모 미리보기를 review에 기록한다. history에도 제외/보류 결과를 저장한다. DUP는 기존 발행 기록을 보존하며 리포트에만 기록한다. 후보 이력 저장이 실패하면 커서를 보존한다.

`published`는 기존 호환 필드이며 비-live에서는 시뮬레이션 수다. `actual_published`, `simulated`, `publish_attempts`, `processed`, `deferred`, `model_usage`를 별도로 확인한다. 복구 댓글이 포함되면 신규 수집만을 분모로 하는 발행률은 null이며 전체 처리 건 기준 발행률을 사용한다. 루트 조회는 최대 100 ID씩 남은 읽기 예산 범위 안에서 수행하고 실제 호출 수를 기록한다.

DB audit의 `unresolved_publications`는 PUBLISHING/UNKNOWN 등 검토 대상 수를 표시한다. 이 값 자체로 정상 댓글 전체를 중단하지는 않는다.

## 운영 적용 전 확인

1. 개발 브랜치의 테스트 결과와 변경 파일을 검토한다.
2. 실제 원문/부모/루트를 사용한 dry_run에서 오분류와 최종 답글을 검수한다. 단위테스트는 실제 문장 품질 평가를 대신하지 않는다.
3. shadow로 평가할 때 live 커서와 별도 namespace를 사용한다. 기존 live 행과 겹치면 저장 가드로 해당 shadow 이력이 저장되지 않을 수 있다.
4. 타인 스레드와 링크 검토는 기본 비활성으로 시작하고, 표본 검수 후 각각 회당 저상한으로 확대한다.
5. 결과 불명 건은 댓글 원문·reply 대상·X 실제 게시 내역·알림의 응답 ID를 대조한다. 미발행이 확인되기 전 이력 삭제/상태 초기화/재발행을 하지 않는다.

긴급 정지는 기존 `REPLY_ENABLED=false`다. 이전 코드로 롤백할 때 새 상태/큐 정보를 모르는 버전이 UNKNOWN 이력을 재처리할 수 있으므로 live를 정지하고 미해결 상태를 먼저 확인한다.

## 3인 리뷰 후 보강

- 결과 불명 요청도 같은 실행의 일일·타인 스레드 상한을 점유한다. 명시적 미발행 응답만 슬롯을 반환한다.
- 발행 claim 시각을 created_at에 기록하여 전날 보류 건의 오늘 발행도 당일 집계한다. 원 댓글 시각은 metadata에 유지한다.
- 과거 PUBLISH_FAIL과 명시적 거절·지출 상한·재시도 소진은 멘션 재수집에서도 자동 재발행하지 않는다.
- 새 멘션과 복구 목록이 겹쳐도 저장된 시도 횟수를 읽는다. 복구 조회는 최대 500행을 검사해 유효 건 최대 100건을 돌려준다. 500행을 넘는 backlog는 다음 실행에서도 지연될 수 있으므로 운영 지표로 확인한다.
- 생성은 남은 회당·일일 슬롯에 맞춘 창 단위로 수행한다. 게이트 탈락으로 비면 뒤 후보를 추가 생성한다.
- 부정된 긍정·금지 표현은 맥락 분류로 보낸다. 일반적인 시장 칭찬은 계정 칭찬으로 단정하지 않는다.
- 피부색·ZWJ·국기 조합을 하나로 세며, 수동 패턴 밖 Unicode 전체 emoji 지원은 보장하지 않는다.
- 예산 조회 장애와 예산 행 부재를 구분한다. 조회 장애는 외부 호출 전에 중단한다.
- 이미 발행됐거나 보호된 상태는 정적 스킵보다 먼저 확인하여 원 이력 보존과 커서 진행을 함께 보장한다.
