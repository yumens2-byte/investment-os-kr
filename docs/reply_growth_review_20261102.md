## 결론
일일 총상한 확대보다 작성자 제한과 응답 범위가 우선이다. 최근 7회 live 실행의 신규 수집은 39건, 확인된 발행은 7건이다. 재처리 후보가 있으므로 7/39를 전환율로 사용하지 않는다. 수집/후보/발행은 로그 관측이며 X 화면을 별도로 대조한 결과는 아니다.

## 현재 처리 흐름
승인 runtime 검사/전체 테스트 → live 확인 → DB 사전 점검 → 신규 멘션 및 재처리 수집 → 정적 필터/중복 → 대화 루트 검증 → 분류 → 제한된 창 단위 후보 생성 → 의미/역할/유사도 게이트 → 작성자/대화 슬롯 예약 → 발행 claim → X 발행 → 결과 및 커서/예산 저장.
UNKNOWN 결과는 재발행하지 않는다. 배포 main과 승인 runtime은 독립적이다.

## 구현한 변경
1. 최근 답글 순서 수정: DB 내림차순 30건에 [-10:]를 적용해 오래된 10건만 전달하던 문제를 수정. 생성부 내부는 시간순으로 유지해 최신 10건과 같은 실행의 추가 발행을 일관되게 참조한다. 유사도 검사는 전체 30건을 유지한다.
2. X 경로만 소재 보존 지시 추가: 짧은 관찰도 구체적인 대상을 유지하며 심리/수치/전망을 만들어내지 않도록 한다. 공통 생성기의 기본 호출과 Facebook 호출 프롬프트는 그대로다.
3. 요약 다운로드: GitHub 인증 헤더가 signed storage redirect에 따라가지 않게 제거한다. 해당 run의 정확한 이름과 만료되지 않은 artifact만 선택한다. 최근 요약 10건에서 401을 확인했고 기존 urllib 코드의 헤더 전달 결함을 수정했다. 실제 GitHub 실행으로 401 해소 확인은 아직 남아 있다.
4. 요약 관측값이 없으면 후보·분류 통과·수집 포화를 0/False로 쓰지 않고 미확인으로 표시한다. candidates는 초안 수가 아니라 루트 검증 통과 후보로 표기한다.

실제 표본(41285472171 artifact)의 댓글은 '시장폭 플러스가 은근 눈에 들어오네요', 발행 답글은 '시장 분위기가 눈에 띄시나 봐요.'였다. 구체 지표가 추상적 표현으로 바뀐 사례다. 개선 프롬프트는 소재 유지를 요구하지만 실제 생성 품질 향상을 측정한 것은 아니다.
