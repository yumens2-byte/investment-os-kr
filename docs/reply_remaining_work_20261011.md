## 개발 결과

기준 소스: main `0f07ceb2a50501052df1e07c4255ef0eb11712bb`.
상대가 운영자의 지표·자료 정리를 칭찬했을 때 이를 상대의 작업으로 잘못 감사하는 오류를 보완했다.

- 명시적인 자료 효용 칭찬은 SUPPORTIVE_NEUTRAL 라벨이어도 PRAISE 의도로 분류한다.
- 생성 프롬프트에 자료 작성자와 읽은 사람의 역할을 명시한다.
- `GATE_ROLE_REVERSAL`로 자료 작성자를 뒤집은 초안을 차단한다.
- 기존 파이프라인의 안전 풀 대체를 이용한다. 대체 문구도 검사에 실패하면 발행하지 않는다.
- X·Facebook이 공유하는 생성 지침과 게이트를 변경한다. Facebook 회귀도 검증했다.
- 인식은 명시된 한국어 패턴에 한정되며 모든 의미상의 역할 반전을 탐지하지는 못한다.

검증: 전체 844개 테스트 통과, 관련 회귀 102개 통과, CI 정적 검사 대상 및 신규 테스트 ruff 통과, diff 검사 통과.
테스트 외부 API·DB는 대역이다. 운영 DB 조회는 아래 증거 확인을 위한 SELECT만 수행했다.

## 정기 실행 빈도

조사 구간: 2026-10-04 09:37~2026-10-11 09:37 KST.
기준·최신 커밋 워크플로의 cron은 UTC `17 1,4,9,13 * * *`로 하루 4회다.
조회한 최근 실행 목록은 구간 전체를 포함하며, X Reply Engine은 정기 14회와 수동 1회였다.
정기 14회 중 2회는 테스트 실패이며, 나머지 12회는 성공이다.
추가 수집기는 조건부 작업이 스킵되었으며 실제 수집·heartbeat 수행 증거가 없다.

실행 created_at은 예정 cron 슬롯의 시간과 다르며, 이것만으로 어느 슬롯이 지연·누락됐는지 확정할 수 없다.
워크플로 스케줄 자체는 확인했지만 이벤트의 schedule 원문, 플랫폼 대기 기록, GitHub 측 장애 증거가 없어 원인은 미확인이다.
cron을 바꾸거나 독립 감시기를 활성화하지 않았다. 실행 빈도 회복을 처리량 증량 효과로 간주하지 않는다.

## 노션 보완

주간 가이드에 최신 실행 환경으로 확인한 3/12/4 적용 상태와 DB로 확인한 cap 만료를 추가한다.
신규 수집 적격 코호트 작성률은 3/4=75%의 확인된 발행 비율이며, 결과 불명 1건 때문에 최종 비율은 미확정이다.
처리량 증량보다 결과 불명 확인과 문구 품질 보완을 우선한다.

## 후속 통합 테스트

PR #25 대상 추가 SDK 연계 4개를 검증했다. 실제 Tweepy 응답 파서와 PostgREST SDK를 사용하되
X HTTP, DB HTTP 및 모델 응답은 오프라인 대역으로 대체했다.

1. live: 수집 → 잘못된 모델 초안 → 역할 게이트 → 안전 대체 → DB claim → X 요청 → 발행 결과 저장.
   전송 문구와 저장 문구가 일치하고 답글 ID가 기록된다.
2. shadow: 안전 문구를 기록하되 X POST는 0회, 실발행 0·시뮬레이션 1로 구분된다.
3. dry_run: 안전 대체를 검증하되 DB 변경 요청과 X POST는 모두 0회다.
4. 안전 대체 후보가 없으면 GATE_ROLE_REVERSAL 이력을 저장하고 claim·발행 시도는 0회다.

기존 결과 불명 재실행 차단, 수집/복구, 중복 방지, 만료 처리 통합 회귀도 통과했다.
SDK 통합 20개, SDK·Facebook 파이프라인·역할 회귀 묶음 68개,
전체 회귀 848개 통과. 변경 테스트 ruff 및 diff 검사 통과.
외부 운영 DB 쓰기·실발행·main 병합은 수행하지 않았다. 실제 X 게시 확인과 정기 실행 원인 미확정은 그대로 남는다.
